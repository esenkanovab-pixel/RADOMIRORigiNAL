# Django Blog + Nomad Tours

Это предыдущий проект django-blog-crud, дополненный приложением tours.
Сохранены blog (List/Detail и счётчик просмотров) и articles (CRUD статей), их миграции и тесты.
Один manage.py, одна база SQLite, единая админка и пользователи.

## Запуск в Windows / VS Code
Распакуйте архив и откройте папку django-blog-crud с manage.py.
```powershell
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python manage.py migrate
.venv\Scripts\python manage.py seed_blogs
.venv\Scripts\python manage.py seed_demo
.venv\Scripts\python manage.py createsuperuser
.venv\Scripts\python manage.py runserver
```
Откройте http://127.0.0.1:8000/ . Активация окружения не требуется.
В Linux/macOS создайте окружение через python3 и используйте .venv/bin/python.

## Разделы
- /blog/ — прежний блог, каждый GET детальной страницы прибавляет просмотр.
- /articles/ — прежний CRUD статей.
- /tours/ — каталог туров; сотрудник может создавать, изменять и удалять туры.
- /profile/ — профиль туриста, /bookings/ — личные покупки.
- /accounts/login/ — вход тем же пользователем, что создан в админке.
- /admin/ — категории, выезды и подтверждение посещения (attended) в покупке.
- /docs/ — документация проекта и бизнес-правила.
- /admin/doc/ — Django admindocs: модели и представления всех приложений. Войдите сотрудником с нужными разрешениями.

## Связи и ограничения туров
User–Profile: 1:1. Tour–Departure и Booking–Comment: 1:N. Tour–Category: M:N.
Один человек может приобрести один тур на точную дату и время старта. Другой день или час разрешены. Ограничение базы предотвращает повторную покупку.
Несколько комментариев разрешены только владельцу покупки после старта выезда и подтверждения посещения сотрудником.
Конный, пеший и мото — категории; смешанный тур может иметь несколько категорий.
Покупка учебная, без банковской оплаты. Пересечение длительности маршрутов не проверяется.
Время выезда с покупками защищено формой админки; прямые изменения через ORM/SQL должны соблюдать то же правило, DB-триггер не добавлен.

## Проверка
```powershell
.venv\Scripts\python manage.py test -v 2
```
Все старые и новые тесты запускаются одной командой. Проверено: 87 тестов — OK. Фактический вывод — reports/combined_tests.txt.
Реестр 58 тестов туров — reports/tours_testing.md; код — tours/tests.py.
Прежние отчёты сохранены в reports/ как исторические результаты.

## Если у вас есть своя база из старого проекта
Сделайте резервную копию старой папки и db.sqlite3. Архив не содержит рабочей базы.
Можно перенести копию вашего db.sqlite3 в эту папку рядом с manage.py и выполнить migrate.
Не удаляйте существующие миграции blog и articles. Новая миграция tours создаст отдельные таблицы.
Если вы самостоятельно меняли исходный код после скачивания старого проекта, эти изменения нужно объединить отдельно: этот архив основан на последней ранее выданной чистой версии.

Python 3.10+. Для публикации отдельно настройте секрет, DEBUG, домены и HTTPS.
Django admindocs: https://docs.djangoproject.com/en/5.2/ref/contrib/admin/admindocs/
