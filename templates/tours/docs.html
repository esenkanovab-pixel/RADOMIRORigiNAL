Документация Django Blog + Nomad Tours

Один Django-проект, общие настройки, пользователи и база данных. Приложение blog: список и детали статей со счётчиком просмотров. Приложение articles: CRUD статей. Новое приложение tours: маршруты, категории, выезды, покупки и комментарии. Блог доступен на /blog/, CRUD на /articles/, туры на /tours/.

Учебный стартап: бронирование конных и смешанных туров Кыргызстана. Целевая аудитория — туристы и местные жители. Доход — продажа мест в турах. Учебная покупка фиксирует бронирование; банковской оплаты нет.

Связи базы данных

  • 1:1 — User → Profile.
  • 1:N — Tour → Departure, User → Booking, Booking → Comment.
  • M:N — Tour ↔ Category.

Правила

Пользователь может приобрести только один тур на конкретный момент старта, даже если маршруты разные. Другой день или время разрешены. Ограничение не проверяет пересечение длительности туров. Часовой пояс — Asia/Bishkek.

Несколько отзывов разрешены только владельцу покупки после даты выезда и подтверждения посещения сотрудником. Клиент не может передать чужой user или самостоятельно подтвердить посещение.

Отправка данных

  • POST /profile/ — phone.
  • POST /tours/new/ и /tours/ID/edit/ — title, description, price, categories (список ID). Только сотрудники.
  • POST /tours/ID/delete/ — удаление; покупки защищены.
  • POST /departures/ID/book/ — покупка текущим пользователем.
  • POST /bookings/ID/comment/ — text, до 2000 символов.

Категории и выезды создаются через админку; форму выезда с существующими покупками нельзя перенести на другое время. Все формы защищены CSRF. Ошибки: 400 — данные, 403 — посещение/CSRF, 404 — объект, 409 — конфликт покупки.

Django admindocs

Автоматическая документация моделей и представлений формируется из docstrings и help_text. Нужен вход сотрудника с разрешениями.

Тестирование

python manage.py test -v 2

Исходный код всех проверок — tours/tests.py. Фактический результат запуска включён в reports/combined_tests.txt. Тесты используют отдельную временную базу данных.
